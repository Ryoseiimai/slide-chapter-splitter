# スライド章分割ツール

350枚規模のスライドPDFを「章ごと」に分割し、各章のテキストをChatGPT等に貼り付けて
動画ナレーション台本を作れるようにする、ブラウザ完結の単一HTMLツール。

## 手元パス

```
/Users/ryoseiworld/dev/2026-09-02-slide-chapter-splitter/
├── index.html          本体（このファイルを開くだけで使える）
├── README.md           このファイル
└── test/
    ├── make_sample.py  検証用テストPDF生成スクリプト
    └── sample.pdf      生成済みテストPDF（Chapter 1〜4、各5ページ、計20ページ）
```

## 使い方

1. `index.html` をブラウザで直接開く（`file://` でもGitHub Pages配信でもOK。サーバ不要）。
2. PowerPoint/Keynote/Googleスライドの場合は、先に「PDFで書き出し」してからそのPDFを使う。
3. PDFをドラッグ＆ドロップ、またはクリックして選択すると全ページのテキストを読み込む。
4. 自動検出された章の区切り（開始ページ）が一覧表示される。おかしければ「区切りページ番号」欄を
   カンマ区切りで編集し「反映」を押す。自動検出が0件のときは「Nページごとに分割」を使う。
5. 章ごとのカードから、PDF保存／台本用テキストのコピー／テキスト保存（.txt）ができる。
   まとめて欲しい場合は「全章をまとめてZIPで保存」。

## 主要な設計判断

- **外部ライブラリはすべてcdnjs.cloudflare.comから固定バージョンで読み込み**（pdf.js 3.11.174 /
  pdf-lib 1.17.1 / JSZip 3.10.1 / FileSaver.js 2.0.5）。事前に全URLの実在（HTTP 200）を確認済み。
- **全処理をブラウザ内で完結**させ、アップロード先を持たない（機密スライド前提の要件）。
- **章の自動検出**は各ページ先頭200文字の各行に対して3種類の正規表現（第○章／Chapter・Section等／
  STEP）を順に評価し、最初に見つかった行をタイトル候補として採用。同一章タイトル（空白除去して正規化）
  が連続するページはスキップし、誤って1ページごとに章が割れないようにしている。1ページ目は常に章の始まり
  として扱う。
- **手動修正**は「区切りページ番号」の直接入力を正とし、自動検出結果を初期値として渡すだけにした。
  非エンジニアでも「数字を書き換えて反映を押す」だけで直せるようにするため。
- **ファイル名の安全化**：章番号ゼロ埋め＋タイトルから使用不可文字（`\ / : * ? " < > |`）を除去し、
  30文字で切り詰め。空になった場合は「無題」を割り当てる。
- **画像化スライドの検知**：章内の抽出テキスト合計が50文字未満なら、テキストが取れていない旨の
  注意書きをカードに表示し、ユーザーが原因（画像化されたPDF）に気づけるようにした。

## 意図的に省いた対応（コード内にも同内容のコメントあり）

- **PPTX / Keynote / Googleスライド形式は非対応**。PDF書き出しをユーザーに促す一言のみで対応。
  本格対応する場合はLibreOffice headless等でサーバサイド変換してPDF化する工程を別途用意する必要がある。
- **目次ページの誤検出**：目次ページに「第1章」「Chapter 1」などの文字列が並んでいると、それぞれが
  独立した章の開始点として誤検出される可能性がある（同一タイトルの重複除去はしているが、目次内の
  複数の異なる章名が列挙されている場合は防げない）。本格対応する場合は、検出行の周辺レイアウト
  （フォントサイズ・ページ内の行数密度など）から「目次らしいページ」を除外するヒューリスティクスが
  必要。現状は手動修正（区切りページ番号の編集）で対応する想定。
- テストPDFはHelveticaフォントで英語見出し（`Chapter 1`〜`Chapter 4`）を使用。日本語フォント
  （`第○章`）を埋め込んだ検証は、環境に日本語フォントの用意ができていないため未実施。
  Pages公開後、別途日本語版スライドPDFでの動作確認を推奨する。

## テストPDFの作り方と結果

`test/make_sample.py` を実行すると `test/sample.pdf`（20ページ、Chapter 1〜4を各5ページ）が
生成される。必要ライブラリは `fpdf2`。

```bash
pip3 install --user --break-system-packages fpdf2   # 未インストールの場合
cd /Users/ryoseiworld/dev/2026-09-02-slide-chapter-splitter/test
python3 make_sample.py
```

生成したPDFに対し、pypdfでテキスト抽出→章検出ロジック（index.html内と同じ正規表現）を
Python側で再現して検証した結果、以下の4箇所が正しく章の開始として検出された。

```
(1,  'Chapter 1: Sample Topic 1')
(6,  'Chapter 2: Sample Topic 2')
(11, 'Chapter 3: Sample Topic 3')
(16, 'Chapter 4: Sample Topic 4')
```

なお最初のテストPDFでは本文中に「Chapter」という単語を含めていたため、本文行まで誤検出される
問題が見つかり、本文の文言を見出しと被らないよう修正した（実運用のスライドで本文中に
「Chapter」等の単語がそのまま出現するケースは稀だが、目次ページの誤検出と同種のリスクとして
上記「意図的に省いた対応」に記載した）。

ブラウザでの実際の動作確認（pdf.js経由の読み込み、UI操作、ZIP/コピー機能など）は別担当が
実施する。
